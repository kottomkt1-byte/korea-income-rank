# 공식 데이터 등록 절차

현재 운영 데이터는 모두 `unavailable`입니다. 아래 절차는 실제 공개 **집계 통계 파일**을 등록하는 방법입니다. 개인의 급여 명세서나 세금 신고서는 등록하지 마세요.

## 근로소득 CSV

1. [공식 원본 페이지](https://www.data.go.kr/data/15082063/fileData.do)를 열고 현재 파일명·귀속연도·신고연도·단위·이용조건을 확인합니다. 확인 시점의 20251231 파일은 **2024년 귀속 / 2025년 신고**, 금액은 **억 원**입니다. 이전 파일의 백만 원 단위를 그대로 적용하면 안 됩니다.
2. 파일데이터의 다운로드로 CSV를 저장합니다. 파일 다운로드는 포털 안내상 로그인 없이 이용 가능하며, API 이용은 별도의 활용신청이 필요할 수 있습니다.
3. 텍스트 또는 스프레드시트에서 실제 머리글을 확인합니다. 확인한 메타데이터의 이름은 `구분`, `인원`, `총급여`, `근로소득금액`, `소득공제금액`, `과세표준`, `결정세액`입니다. 계산에는 **총급여**를 매핑합니다.
4. `data/metadata/worker.template.json`을 작업용 파일로 복사합니다. 원본 전체 인원 합계와 총급여 합계를 계산하고 공식 합계/관련 집계와 대조한 뒤 `expectedTotalPeople`, `expectedTotalSalaryInSourceUnit`을 실제 숫자로 기입합니다. 합계 행이 없는 파일이면 각 구간 합계가 기대 모집단과 일치하는지 검토하고 근거를 `metadata.notes`에 남기세요.
5. `구분`이 `상위 0.1%`, `상위 0.2%`, …, `상위 100%` 또는 숫자 하나로 표시된 **비중복 구간의 누적 끝점 라벨**이면 `rankFormat: "cumulative-endpoint"`를 사용합니다. `0~0.1%`, `0.1~0.2%` 같은 라벨은 `"range"`를 사용합니다. 행의 숫자가 누적 합계인지 구간 합계인지 반드시 구별하세요. 실제 인원이 누적값인 표는 직접 이 형식으로 등록할 수 없습니다.
6. 출처와 모집단 확인을 끝낸 뒤에만 `sourceReviewed`, `populationReviewed`를 `true`로 바꿉니다. 귀속연도·신고연도·공개일·확인일·원본 URL을 갱신합니다.
7. 인코딩에 맞춰 검증만 먼저 실행합니다.

```bash
npm run data:import -- --file /absolute/path/official.csv --manifest /absolute/path/worker-reviewed.json --encoding euc-kr --dry-run
```

UTF-8 파일은 `--encoding utf-8`을 사용합니다. CP949 일반 한글 CSV는 `euc-kr` 디코더로 읽습니다. 디코딩 오류는 무시하지 않습니다.

8. 합계와 기준연도 비교를 확인한 다음 `--dry-run` 없이 실행합니다. 성공 시 원본·검토 manifest가 `data/raw/`에 복사되고 SHA-256이 운영 JSON에 기록됩니다. 운영 파일 교체는 검증 성공 후 원자적으로 수행됩니다.
9. `npm run check`와 `npm run test:e2e`를 실행하고 실제 금액 몇 건을 원본 구간 평균과 대조합니다. `/statistics`에서 인원·평균·그래프·출처를 확인한 뒤 커밋·재배포합니다.

구간별 인원은 전체 인원의 0.1% 또는 1%에서 3명 이상 차이가 나면 거부합니다. 이는 구간 라벨을 누적 인원으로 오독하는 것을 방지하는 검증입니다. 공식 자료의 분할 방식이 바뀌면 조용히 우회하지 말고 스키마·테스트를 함께 검토하세요.

총급여 합계의 반올림 차이는 원자료의 단위와 반올림 규칙에 근거가 있을 때만 `sumToleranceInSourceUnit`에 입력합니다. 기본 0, 허용 상한 55 원본 단위이며 임의로 크게 설정할 수 없습니다.

## 사업소득 CSV/XLSX

1. [TASIS](https://tasis.nts.go.kr/)에서 **3-2-5 소득금액 규모별·업태별 사업소득 신고 현황**을 확인합니다. 실제 표 식별자·조회 경로·귀속연도·신고연도·소득 정의·주석·라이선스를 기록합니다.
2. 인원이 개인 기준인지, 업태·사업장 중복이 있는지, 전체 행이 중복 제거된 수치인지 확인합니다. 프리랜서의 포함 범위와 근로소득 병행자의 포함 여부를 기록합니다. 미확인 내용은 임의로 예/아니오 처리하지 마세요.
3. 비교 가능한 **소득금액 구간별 고유 신고인원**만 선택합니다. 표의 전체·업태·소계 행을 모두 더하면 안 됩니다. 고유 개인 분포를 만들 수 없다면 `unavailable`을 유지합니다.
4. 구간을 `하한`, `상한`, `인원` 열로 정규화한 CSV/XLSX를 준비합니다. 모든 구간은 `[하한, 상한)`입니다. 원본이 상한 포함 표기이면 원 단위 경계로 정확히 바꾸고 변환 근거를 보존합니다. 열린 끝 구간만 `OPEN`이라는 문자열을 씁니다. 빈 셀·`-`·`*`·비공개를 0이나 무한대로 취급하지 않습니다.
5. 원본 파일도 별도 보존하세요. 정규화 파일을 입력한 경우 CLI가 기록하는 해시는 **정규화 입력 파일**의 해시입니다. `metadata.notes`에 원본 파일의 해시, 변환 방법, 표 주석과 대조 근거를 추가합니다. PDF·다중 헤더·병합 셀·수식이 있는 원본은 자동 해석하지 않으므로 값만 담은 단일 헤더 표로 정규화하고 검토하세요.
6. `data/metadata/business.template.json`을 복사하고 실제 모집단·연도·컬럼·합계·단위와 `countingUnit: "unique-person"`을 입력합니다. `includesMixedEarners`는 `yes`/`no`/`unknown` 중 원자료에서 확인된 상태를 기록합니다. `unknown`이면 해당 포함 여부를 사용자 안내 notes에도 명시합니다.
7. 여러 업태 행이 있다면 `filter: { "column": "업태", "equals": "전체" }`로 검증한 전체 행만 선택합니다. 그런 전체 행이 없는 경우 업태별 인원을 합쳐 대신하지 마세요.
8. 검증·등록·테스트·재배포를 수행합니다.

```bash
npm run data:import -- --file /path/to/reviewed-business.xlsx --manifest /path/to/business-reviewed.json --dry-run
npm run data:import -- --file /path/to/reviewed-business.xlsx --manifest /path/to/business-reviewed.json
```

XLSX는 첫 행을 헤더로 읽습니다. `sheet`를 지정하거나 첫 시트를 사용합니다. 오래된 `.xls`는 `.xlsx`로 변환해야 합니다.

## 실패 처리와 갱신

- 컬럼 누락, 숫자 비공개, 중복/역전/누락 구간, 인원 합계 오류, 연도 불일치, 미검토 출처는 등록을 중단하며 기존 운영 파일을 보존합니다.
- 사업소득에서 음수 구간이 없다면 음수 입력을 0으로 바꾸지 않고 해당 값의 계산을 중단합니다.
- 기존 검증 자료보다 오래된 귀속연도로 교체하면 중단합니다. 이전 자료와 다른 정의·모집단을 연도만 보고 합치지 마세요.
- 원본이 바뀌면 해시·귀속연도·공개일·라이선스·검토 주석도 갱신합니다.
- `sourceReviewed: true`는 관리자의 검토 기록이지, CLI가 공식 통계의 의미를 자동으로 입증했다는 뜻이 아닙니다. 문서와 원본의 대조 검토가 필요합니다.
- 등록 후 재빌드 전에는 브라우저 결과가 바뀌지 않습니다. 통계 JSON을 브라우저에서 업로드하는 관리자 기능은 제공하지 않습니다.
