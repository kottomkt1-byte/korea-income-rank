# 배포·공유 설정

## Vercel

저장소 루트를 Next.js 프로젝트로 Import하고 Node.js 22 이상, `npm ci`, `npm run build`를 사용합니다. 별도 데이터베이스나 서버 비밀키는 필요하지 않습니다.

`NEXT_PUBLIC_SITE_URL=https://실제-도메인`을 Production 환경변수로 지정하고 재배포합니다. canonical과 sitemap이 이 값을 사용합니다. 사이트 주소가 없거나 근로소득 데이터가 미검증이면 noindex입니다. 실제 데이터가 없는 상태에서 검색 노출을 강제로 켜지 마세요. 데이터 파일과 공개 환경변수는 빌드 결과에 포함되므로 변경할 때마다 재빌드합니다.

현재 저장소는 Vercel 호환 Next.js 앱이며 실제 배포는 하지 않았습니다. 로컬 실행만으로 공개 URL이 생성되지는 않습니다.

## 카카오톡

1. [Kakao Developers](https://developers.kakao.com/)에서 운영할 앱을 준비합니다.
2. 웹 플랫폼에 배포 도메인을 등록하고 카카오톡 공유 사용 조건과 현재 SDK 문서를 확인합니다.
3. 앱의 **JavaScript 키**를 `NEXT_PUBLIC_KAKAO_JS_KEY`에 설정합니다. JavaScript 키는 공개되는 클라이언트 식별자입니다. Admin 키나 REST API 비밀키를 넣으면 안 됩니다.
4. 재배포한 뒤 실제 도메인에서 카카오톡 공유를 확인합니다. 브라우저 팝업 정책이나 카카오 계정 상태에 따라 동작이 달라질 수 있습니다.

SDK는 클릭 시에만 로드됩니다. 키가 없으면 '카카오톡용 링크 복사' 버튼이 홈 URL을 복사하므로 복사한 링크를 사용자가 카카오톡에 붙여넣을 수 있습니다. 일반 링크 복사·Web Share·PNG 저장도 항상 대체 경로로 제공됩니다. 연결된 앱 키가 없어 실제 카카오 발송은 검증하지 않았습니다.

## 개인정보

입력은 브라우저 메모리에서만 처리하며 페이지 URL, 서버 요청, 브라우저 저장소에 금액을 쓰지 않습니다. 원본 통계는 공공 집계자료만 등록합니다. 사용자 금액을 분석 이벤트에 추가하지 마세요. 에러 리포팅·히트맵·광고를 나중에 설치하면 입력 DOM 수집 여부를 확인하고 개인정보 안내를 갱신해야 합니다.

## 광고 예약 영역

`NEXT_PUBLIC_ADS_ENABLED=false`가 기본입니다. `true`는 높이를 확보한 '광고' 예약 영역만 표시하며 광고 스크립트나 AdSense 계정 연결을 자동 설치하지 않습니다. 결과 이후·시뮬레이터 이후·FAQ 중간·통계 페이지에 슬롯이 있습니다. 공급자 추가 시 슬롯의 높이를 보존하고 광고임을 명시해야 합니다.

## 운영 확인

- 공식 원본이 검증된 커밋인지 확인
- 실제 HTTPS 도메인에서 canonical·OG·robots·sitemap 확인
- 모바일 입력·재계산·PNG·공유 대체 경로 확인
- 개인정보 안내가 실제 호스팅/추가 스크립트와 일치하는지 확인
- 소득 통계의 귀속연도와 원본 갱신 여부 정기 점검

공식 통계가 갱신되면 `docs/DATA_IMPORT.md`에 따라 검증한 후 PR로 검토하고 배포합니다. 자동으로 임의의 표를 크롤링해 운영 통계를 바꾸지 않습니다.
